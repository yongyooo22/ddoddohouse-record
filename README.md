# 또또하우스 기록장

우리 모임이 함께 한 **보드게임 · 머더미스터리 · 방탈출**을 기록하는 비공개 웹앱이에요.
휴대폰에서 쓰기 좋게 만들었고, 노트북·태블릿처럼 가로로 넓은 화면에서는 왼쪽 메뉴와 여러 단 화면으로 바뀌어요. 비밀 링크를 받은 사람만 열 수 있어요.

- **게임 정보와 플레이 기록을 나눠요.** 게임·작품·테마는 한 번 등록하고(종류 · 이름 · 대표 이미지 · 내 소장 여부 · 보드게임은 인원·예상 시간·장르 · 머더미스터리는 태그 · 방탈출은 매장·지점), 플레이 기록은 그 게임을 골라 날짜별로 남겨요. 같은 게임으로 몇 번이든 기록하고, 별점·감상은 판마다 따로예요.
- **기록은 가볍게**: 그날의 기록은 **게임 · 날짜 · 별점 · 감상(짧게 한 줄도 좋아요)**을 남기고, 함께한 사람은 선택이에요. 플레이 사진·세부 평가는 받지 않아요. 예전에 남긴 결과·세부 정보·사진은 그대로 보존돼요(화면에서 입력만 빠졌어요).
- **보드게임 점수 → 순위 자동**: 함께한 사람마다 **점수**를 적으면 순위가 바로 매겨져요(높은 점수가 1등, 같은 점수는 같은 순위 — 1·2·2·4등). 골프처럼 낮을수록 좋은 게임은 **낮은 점수가 이겨요**를 켜요. 1등이 그 판의 승자로 저장되고, 통계의 **보드게임 랭킹**에 모여요.
- **머더미스터리**: 위에 더해 **내 역할**(내가 맡은 역할, 한 줄)을 적고, 함께한 사람마다 **맡은 역할**도 적을 수 있어요(나의 역할 칸은 '내 역할'과 같은 값). 상세의 **함께한 멤버**에 멤버마다 역할이 나와요. 스포일러로 가리면 이름은 보이고 역할만 **역할 보기**로 가려요. 작품의 태그(추리중심·반전 …)는 게임 정보를 등록할 때 달아요.
- **나(이 기기의 나)**: 멤버 중에서 '이 기기에서는 내가 이 사람'을 한 번 골라 두면(주요 화면 **오른쪽 위의 '나 고르기' 버튼**, 멤버 프로필의 **이 기기에서 나로 설정**, 머더미스터리 폼의 **나 고르기**) 그 버튼에 내 이름이 보이고(누르면 바꾸기·해제) 새 기록에 내가 자동으로 참여자로 들어가고, 내 역할이 내 이름으로도 저장돼요. 기기마다 따로 저장하고 보안 기능은 아니에요(입장 코드는 그대로). 멤버 프로필에는 **내가 맡았던 역할**(작품·역할·날짜·별점, 가린 기록은 '가려진 역할')이 모여요.
- **방탈출**: 매장·지점은 테마(게임 정보)에 등록해 두고, 기록에는 별점·감상을 남겨요.
- 공통: 별점(반 개 단위), 감상(예전 한줄평·후기를 하나로), 스포일러 가리기.
- 게임과 날짜만 있으면 저장돼요. 별점·감상·내 역할은 선택이에요.

### 기록 쓰기 (가운데 한 줄 폼)
- **종류 · 게임 · 날짜 · 별점 · (머더미스터리: 내 역할) · 감상**을 적어요.
- **게임 고르기**: 고른 종류의 게임·작품·테마를 이름으로 검색해서 골라요. 결과에는 작은 대표 이미지와 이름, `2~4명 · 60~90분 · 전략` 같은 요약이 보여요. 고른 게임은 요약으로 보이고 **변경**으로 다시 고르거나 ✎로 게임 정보를 고쳐요. 머더미스터리·방탈출은 이미 해 본 멤버도 알려 줘요.
- 찾는 게임이 없으면 검색 결과 맨 아래 **＋ 새 게임 등록** → 작은 창(지금 종류·검색어가 채워진 채)에서 이름만 적어 등록하면 창이 닫히고 그 게임이 골라져요. 쓰던 날짜·감상은 그대로예요. 같은 이름이 이미 있으면 먼저 보여 주고, 다른 판본이면 그대로 따로 등록돼요(이름만으로 합치지 않음). 예전 기록에만 있던 이름도 검색 결과에서 눌러 바로 등록할 수 있어요.
- 아래 작은 버튼으로 더 적어요: `＋ 함께한 사람`(선택 — 안 골라도 기록돼요, 나는 기본으로 들어가 있어요). 보드게임은 `함께한 사람 · 점수`, 머더미스터리는 `함께한 사람 · 역할`로 보이고, 고른 사람마다 점수(순위는 자동)나 맡은 역할을 적는 칸이 생겨요. 접기로 접어도 값은 그대로, 버튼에 `연경, 영식` 같은 요약이 보여요. 기존 기록을 고칠 때 값이 있는 칸만 펼쳐져요. 예전 기록의 세부 정보·태그·사진은 폼에 나오지 않지만, 고쳐서 저장해도 그대로 남아요. 점수 없이 순위만 매겨 둔 예전 기록도 점수를 새로 적기 전까지 그 순위가 그대로예요.

- 종류는 폼 안에서 바꿀 수 있어요(새 기록만). ＋ 버튼으로 열면 마지막으로 기록한 종류로 시작해요.
- 휴대폰에서 글을 쓰는 동안에는 아래 저장 줄을 붙여 두지 않아 키보드·마지막 칸을 가리지 않아요.

### 소장 탭
- '내가 소장한 게임'으로 표시한 보드게임·머더미스터리만 게임별로 모아 봐요(방탈출 테마는 소장 개념이 없어요). 대표 이미지, 인원·시간·장르, 몇 번 했는지, 최근에 한 날짜, 평균 별점이 보이고 최근 순·많이 한 순·별점순·이름순으로 정렬해요.
- **게임 등록**: 소장 탭에서 열면 '내 소장'이 기본으로 선택돼요(기록 폼에서 열면 선택 안 됨). 보드게임은 인원(최소~최대, 한 칸만 적으면 고정 인원 — 1인 게임도 돼요)·예상 시간(분, 하나 또는 범위)·장르(추천 칩 여러 개 + 직접 추가)를 함께 넣을 수 있어요. 머더미스터리는 **태그**(추리중심·반전 …, 추천 칩 + 직접 추가)를 달 수 있어요. 여러 개는 **계속 등록**으로 이어서 넣어요.
- 게임 카드를 누르면 **게임 상세**로 가요: 대표 이미지 · 인원·시간·장르(방탈출은 매장·지점) · 몇 번 했는지 · 평균 별점, **플레이 기록하기**(그 게임이 골라진 새 기록), 정보 수정, 소장에서 빼기, 그 게임의 플레이 기록 목록. 게임 정보 전의 예전 기록 이름은 '게임 정보로 등록' 버튼이 대신 보여요.
- 게임 메뉴(⋯): 기록 보기 · 이 게임으로 새 기록 쓰기(게임이 골라진 폼) · 게임 정보 수정 · **소장에서 빼기**(소장 여부만 바꾸고 게임 정보와 지난 기록은 그대로) · 기록이 없는 게임은 게임 정보 삭제.
- 게임 정보 전의 예전 기록은 그대로 둬요. '내 소장'으로 남긴 예전 기록은 소장 탭에 계속 보이고, 같은 종류·같은 이름의 게임이 딱 하나 등록돼 있으면 그 게임 기록으로 모아서 보여 줘요(보여 줄 때만 묶고 기록은 바꾸지 않아요).

### 화면
- 크림색 바탕에 흰 기록 영역, 차분한 진초록 포인트(저장 버튼·선택 상태)를 쓴 담백한 디자인이에요. 입력칸·버튼은 44~48px, 그림자와 큰 아이콘 바탕은 줄였어요. 로고와 앱 아이콘은 줄 쳐진 노트에 연필로 쓰는 모습(연필심이 닿은 마지막 줄은 금빛)이고, 카드 모서리는 16~20px로 맞췄어요. 화면 맨 아래에는 작고 옅게 '© 2026 제작: 김연경(이메일)' 문구가 있어요(이메일은 누르면 메일 쓰기). 글꼴은 Pretendard(사이트에 직접 넣어 둠)예요.
- 홈: **플레이 기록** 제목 → 낮은 요약 띠(전체 · 이번 달 · 보드게임 · 머더미스터리 · 방탈출, 항목명과 숫자를 붙여 '보드게임 12회'처럼. 휴대폰처럼 좁은 화면(520px 미만)의 요약 띠와 4칸 종류 필터에서만 '머더미스터리'를 '머미'로 줄여 보여요) → 최근 기록 → **내 소장 게임**(최대 6개를 작은 표지로, 누르면 게임 상세). 기록이 없으면 '첫 플레이를 기록해 보세요' 한 줄과 **＋ 기록 남기기** 버튼만 있는 낮은 상자, 소장 게임이 없으면 작은 **＋ 소장 게임 등록** 버튼만 보여요. 멤버는 기록하면서 바로 추가할 수 있어서 홈에서 먼저 등록하라고 안내하지 않아요. '이번 달 가장 많이 함께한 멤버'는 멤버 화면에 있어요.
- 통계 → 보드게임: 플레이 수 · 최다 우승자 · **보드게임 랭킹**(1등 횟수 순, 같으면 1등 비율 → 평균 순위. 1~3위는 메달 색, 판 수 · 평균 순위 · 1등 비율도 보여요. 점수·순위를 적은 경쟁·팀전 판만 세고 협력 게임은 빠져요) · 많이 한 게임 · 멤버별 승률.
- 기록 카드: 대표 이미지(예전 기록에 붙여 둔 첫 사진, 없으면 게임 대표 이미지) · 종류 · 제목 · 날짜 | 점선 | ★ 별점 · 감상의 첫 부분(두 줄). 스포일러 기록의 감상은 카드에서도 열기 전까지 가려요. 노트북에서 2~3열, 휴대폰에서 1열.
- 기록 목록: 위에 종류 탭, 검색(제목·매장·역할·감상) · **필터** 버튼 · 정렬. 필터(함께한 멤버·소장)는 버튼으로 접어 두고, 적용 중인 필터는 칩으로 보여 하나씩 또는 **모두 해제**로 풀어요.
- 휴대폰: 아래 탭 막대(홈 · 기록 · 소장 | ＋ | 통계 · 멤버 · 설정, 새 기록 버튼이 가운데) · 태블릿(768px~): 왼쪽 아이콘 레일 · 노트북(1200px~): 왼쪽 사이드바(232px). 레일·사이드바의 '새 기록'이 주 버튼이라 목록 머리의 같은 버튼은 숨겨요(빈 화면 안내 버튼은 그대로).

## 1. 처음 배포하기 (Vercel)

준비물: GitHub 계정(저장소 `yongyooo22/ddoddohouse-record`), Vercel 계정(GitHub으로 가입하면 편해요). 모두 무료 요금제로 충분해요.

### ① 저장소 가져오기
1. <https://vercel.com> 에 로그인 → **Add New… → Project**.
2. **Import Git Repository** 목록에서 `yongyooo22/ddoddohouse-record` 옆의 **Import**를 눌러요.
   (목록에 없으면 "Adjust GitHub App Permissions"에서 이 저장소 접근을 허용해요.)
3. Framework Preset은 **Other** 그대로, Build Command·Output Directory는 비워 둔 채 **Deploy**.
   → 첫 배포는 아직 저장소(Redis)와 비밀 코드가 없어서 열어 보면 "서버 설정이 아직 끝나지 않았어요"가 나오는 게 정상이에요.

### ② 저장소(Upstash Redis) 연결
1. Vercel에서 방금 만든 프로젝트 → 위쪽 **Storage** 탭.
2. **Create Database**(또는 **Connect Database**) → **Upstash** → **Upstash for Redis** 선택.
3. 이름은 아무거나(예: `ddoddohouse`), 지역은 가까운 곳(예: Tokyo / Seoul), 요금제는 **Free** → 만들기.
4. 만들어진 데이터베이스를 이 프로젝트에 **Connect** 해요.
   → 프로젝트 환경변수에 `KV_REST_API_URL`, `KV_REST_API_TOKEN` (또는 `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`)이 자동으로 들어가요. 둘 중 어느 이름이든 앱이 알아서 읽어요.
   > **주의:** 연결 화면에 **환경변수 접두어(Custom Prefix / Environment Variables Prefix)** 칸이 나오면 **비워 두거나 기본값 그대로** 두세요. 접두어를 바꾸면(예: `MYDB_KV_REST_API_URL`) 앱이 저장소를 찾지 못해 "서버 설정이 아직 끝나지 않았어요"가 계속 나와요.

### ③ 비밀 코드(APP_SECRET) 만들고 넣기
이 값이 곧 **입장 코드**예요. 길고 무작위일수록 안전해요 (16~512자, 영문·숫자·`-`·`_`·`.`·`~`만 — 그래야 앱이 켜져요).

**만드는 법 (둘 중 하나)**
- 컴퓨터 브라우저(크롬 등)에서 아무 페이지나 열고 `F12` → **Console** 탭에 아래를 붙여넣고 Enter:
  ```js
  crypto.randomUUID() + crypto.randomUUID()
  ```
  따옴표 안의 긴 글자(예: `3f9c…-…`)를 그대로 복사해요.
- 터미널이 있다면:
  ```sh
  openssl rand -hex 24
  ```

> 영문·숫자·`-`·`_`·`.`·`~` 만 쓸 수 있어요 (위 방법으로 만들면 자동으로 그렇게 돼요).
> 띄어쓰기·한글·`+`·`/`·`=`·`%`·`&`가 섞인 값(예: `openssl rand -base64`로 만든 값, 문장형 비밀번호)은 공유 링크에서 깨지기 때문에 **앱이 설정 안 된 것으로 보고 켜지지 않아요.**
> 이 README 와 개발 서버에 나오는 `dev-secret-key-1234`는 누구나 아는 값이라 **Vercel 배포에서는 거부돼요.**

**넣는 곳**
1. 프로젝트 → **Settings → Environment Variables**.
2. Key: `APP_SECRET`, Value: 방금 만든 값, Environment: **Production**(과 원하면 Preview) 체크 → **Save**.

### ④ 다시 배포(Redeploy)
환경변수는 **새로 배포해야** 적용돼요.
프로젝트 → **Deployments** → 맨 위 배포의 `⋯` → **Redeploy** → 확인.

### ⑤ 확인
배포가 끝나면 Vercel이 준 주소(예: `https://ddoddohouse-record.vercel.app`)로 아래 링크를 열어 보세요.
인사말과 요약 띠(전체 · 이번 달 · 보드게임 · 머더미스터리 · 방탈출)가 있는 홈 화면이 보이면 성공이에요.

## 2. 친구들에게 공유하는 링크

```
https://<도메인>/#k=<APP_SECRET>
```

예) `https://ddoddohouse-record.vercel.app/#k=3f9c2a…`

- **왜 `#`을 쓰나요?** 주소에서 `#` 뒤 부분(fragment)은 브라우저 안에서만 쓰이고 **서버로 전송되지 않아요.** 그래서 Vercel 접속 기록이나 다른 사이트로 넘어가는 Referer에 코드가 남지 않아요.
  (`https://<도메인>/?key=<APP_SECRET>` 형식도 되지만, 이건 서버 로그에 남을 수 있어서 `#k=`를 권장해요.)
- 링크로 들어오면 앱이 코드를 **이 기기에만 저장**하고, 주소창에서 코드를 **바로 지워요.** 그다음부터는 그냥 주소(또는 홈 화면 아이콘)로 열면 돼요.
- 코드 없이 들어오면 잠금 화면이 나와요. 코드나 링크 전체를 붙여넣어도 열려요.
- **아이폰 "홈 화면에 추가"**: Safari에서 링크로 한 번 연 뒤 공유 버튼 → "홈 화면에 추가". 홈 화면 앱은 Safari와 저장 공간이 따로라서 처음 열 때 잠금 화면이 나오면 **공유 링크를 통째로 복사해 붙여넣기** 하면 돼요.

## 3. 보안은 이렇게 되어 있어요

- **서버에서 읽기·쓰기 모두 막음**: 모든 API(`/api/…`)는 요청마다 입장 코드를 확인해요. 코드가 틀리면 목록 보기도, 저장도 안 돼요. 서버에 `APP_SECRET`이 없거나 16자보다 짧거나 쓸 수 없는 문자가 섞였으면 **아예 아무것도 안 열려요** (설정 실수로 열려 버리는 일이 없게).
- **무차별 대입 차단**: 같은 곳(IP)에서 코드를 20번 틀리면 15분 동안 막혀요. 코드 비교는 시간 차로 추측할 수 없는 방식(SHA-256 + 상수 시간 비교)이에요. 코드를 **아예 안 보낸** 요청(다른 사이트가 몰래 보내게 만든 요청 등)은 틀린 횟수로 세지 않아서, 남이 우리 모임 사람을 일부러 잠가 버릴 수 없어요.
- **링크 코드가 달라도 바로 바꾸지 않음**: 이미 열어 둔 기기에서 코드가 다른 링크(잘린 링크, 예전 링크)를 열면, 서버에서 새 코드가 맞는지 먼저 확인하고 맞을 때만 바꿔요. 틀리면 쓰던 코드와 오프라인 사본을 그대로 둬요.
- **검색엔진 차단**: `robots.txt`, `noindex` 메타 태그, `X-Robots-Tag` 헤더로 검색에 안 나오게 했어요.
- **링크에서 키 자동 제거**: 링크로 들어오면 주소창에서 코드를 즉시 지워서, 화면 캡처나 주소창 복사로 새어 나가는 일을 줄였어요. 다만 **브라우저 방문 기록(과 기기 간 동기화된 기록·주소 자동완성)에는 처음 연 링크가 코드째로 남아요** — 아래 공용 기기 안내를 꼭 봐 주세요.
- **사진도 입장 코드로 보호**: 사진은 `/api/images`로만 받을 수 있고, 이 API도 요청마다 입장 코드를 확인해요. 사진 주소만 알아서는(예: `<img src>`로 불러도) 볼 수 없어요. 앱은 코드를 붙여 받은 사진을 기기 메모리(`blob:`)로만 보여 줘요.
- **사진의 위치 정보(GPS) 제거**: 올리기 전에 휴대폰·브라우저 안에서 사진을 다시 그려(재인코딩) 저장하기 때문에 촬영 위치·기기 정보 같은 EXIF가 모두 빠져요. 서버도 한 번 더 걸러요: JPEG·WebP만 받고(PNG·GIF·SVG 등은 거부) 파일 구조를 끝까지 읽어서 EXIF·XMP·IPTC·주석과 그림 뒤에 덧붙은 데이터(모션 포토 영상 등)를 떼고 저장해요. 그래서 손으로 만든 백업이나 API로 직접 올린 사진도 위치 정보가 남지 않아요. 구조를 읽을 수 없는 파일(앞부분만 JPEG처럼 꾸민 파일 등)은 거부해요.
- **그 밖에**: 외부 스크립트·폰트를 전혀 안 쓰고(CSP `'self'` — 글꼴도 `/fonts/`에서 직접 받음), 사용자가 쓴 글은 항상 글자로만 화면에 넣어서(XSS 방지) 다른 사람이 악성 코드를 심을 수 없어요. API 응답은 캐시되지 않고(사진만 이 기기 브라우저에 비공개로 잠깐 보관 — 서버·중간 캐시에는 안 남음), 오류 메시지에 내부 정보가 나오지 않아요. 다른 사이트 안에 끼워 넣기(iframe)도 막혀 있어요.
- 기기에는 입장 코드와 마지막으로 받은 기록 사본(오프라인 열람용)이 저장돼요. 한 번 본 사진은 브라우저 캐시에 최대 7일 남아요(같은 코드로 다시 열 때·오프라인에서도 보이게). **이 기기에서 잠금 해제 정보 지우기**를 누르거나 코드가 바뀌어 잠길 때는 이 캐시도 비워요(`Clear-Site-Data: "cache"` — 크롬·엣지·파이어폭스 등 지원하는 브라우저에서). 잠길 때는 열려 있던 전체화면 사진·사진 메뉴도 모두 닫혀요.
- **공용·가족 기기에서는**
  1. 링크를 그대로 열지 말고 **시크릿(비공개) 창**에서 열거나, 잠금 화면에 **코드만 붙여넣어** 여세요 (그러면 방문 기록에 코드가 안 남아요).
  2. 다 쓴 뒤 **설정 → 이 기기에서 잠금 해제 정보 지우기**를 눌러요 (이 기기에 저장된 코드·사본·받아 둔 사진 삭제). 캐시 비우기를 지원하지 않는 브라우저(일부 사파리 등)라면 시크릿 창을 닫거나 브라우저의 **캐시된 이미지·파일**도 지워요.
  3. 링크로 열었다면 브라우저 **방문 기록에서 이 사이트 항목도 지워요** (지우기 버튼은 방문 기록까지는 못 지워요).

## 4. 링크(코드)가 새어 나갔을 때

1. 위 ③의 방법으로 **새 APP_SECRET**을 만들어요.
2. Vercel → **Settings → Environment Variables** → `APP_SECRET` → **Edit**로 새 값으로 바꾸고 저장.
3. **Deployments → Redeploy**.
4. 새 링크(`https://<도메인>/#k=<새 코드>`)를 친구들에게 다시 보내요.

예전 코드를 가진 기기는 다음에 열 때 "코드가 바뀌었거나 맞지 않아요"가 뜨고, 그 기기에 저장된 사본도 지워져요. 기록 자체는 서버에 그대로 있어요.

## 5. 사진

### 올리기
- **기록에는 플레이 사진을 올리지 않아요.** 기록 쓰기·수정 화면에 사진 칸이 없고, 붙여넣기·끌어 놓기로도 올라가지 않아요.
- 예전에 기록에 붙여 둔 사진은 그대로 보이고(아래 '보기'), 기록을 고쳐 저장해도 남아요.
- **게임 대표 이미지**: 게임 정보(등록 창·정보 수정)에서 한 장 넣어요. 사진이 없는 기록은 목록에서 이 이미지로 보여요. 대표 이미지도 같은 사진 저장소를 쓰고, 쓰는 동안은 정리되지 않아요(바꾸거나 게임을 지우면 하루 뒤 정리). 저장하지 않고 창을 닫으면 그 창에서 올린 이미지는 바로 지워요.
- 고르자마자 기기에서 줄인 뒤 올려요. 저장 공간을 아끼려고 원본은 긴 변 1280px·350KB 이하의 WebP(안 되는 브라우저는 JPEG), 목록용 작은 사진은 360px·40KB 이하로 줄여요. 이때 **위치 정보(EXIF)가 빠져요.**
- 데스크톱 크롬처럼 HEIC를 못 여는 브라우저에서는 "이 사진 형식(HEIC 등)은 열 수 없어요. 카메라 설정의 ‘고효율’ 사진을 끄거나 JPG로 저장해서 올려 주세요"가 나와요. 아이폰 Safari에서는 HEIC도 그대로 골라도 돼요.

### 보기
- 사진이 붙은 예전 기록은 목록·홈 카드에 대표 사진이 붙고, 상세 화면 위쪽에서 넘겨 보거나 썸네일을 눌러 골라요. 세로·파노라마 사진도 잘리지 않고 전체가 보여요.
- 사진을 누르면 전체화면으로 크게 봐요: 좌우로 넘기기(←/→ 키, 터치 기기는 위쪽의 ‹ › 버튼), ✕·Esc·아래로 쓸기·뒤로가기로 닫기. 닫으면 상세 화면도 마지막으로 본 사진으로 맞춰져요. 원본은 보는 사진부터 받고 양옆은 그다음에 미리 받아요.

### 저장 공간과 정리
- 한도: 기록당 4장, 전체 **3,000장 또는 150MB**(서버가 받는 한 장 크기는 원본 700KB·작은 사진 100KB까지). 사진은 Upstash에 글자(base64)로 저장돼서 150MB면 약 200MB를 차지해요 — 무료 요금제 256MB 안에서 기록이 쓸 자리를 남긴 크기예요.
- **설정 → 사진 저장 공간**에서 사진 수·용량과 한도 대비 막대를 볼 수 있어요.
- **80%를 넘으면** 설정에 찬 정도와 대략 더 넣을 수 있는 장수가 나와요. **가득 차면** 서버가 한도를 넘는 사진은 받지 않아요. 사진과 기록은 따로 세서, 사진이 가득 차도 기록은 계속 저장돼요.
- 기록을 **지우거나**, (예전 앱에서) 사진을 **빼고 저장**하면 그 사진은 **하루 뒤에** 서버에서 지워져요 (그 뒤 누군가 기록을 저장·삭제할 때 함께 정리). 바로 지우지 않는 건, 다른 기기에서 아직 저장하지 않은 폼이 그 사진을 가리킬 수 있어서예요 — 예를 들어 내가 고치는 동안 다른 사람이 기록을 지워서 "새 기록으로 다시 저장"할 때, 또는 예전 앱에서 그 사진을 다른 기록에 가져다 쓰는 중일 때. 다른 기록도 쓰는 사진은 남아요.
- 사진을 모르는 예전 버전 앱(업데이트 전)으로 기록을 고쳐 저장해도 사진은 그대로예요.
- 앱을 닫는 등으로 남은 사진은 **설정 → 사용하지 않는 사진 정리**로 지워요. 어떤 기록에도 쓰이지 않고 **올린 지(기록에서 빠진 지) 하루가 지난** 사진만 지워요. 이 기기에서 쓰던 초안의 사진은 남기지만, 다른 기기에서 하루 넘게 저장하지 않은 초안의 사진은 지워질 수 있어요.
- 저장 공간이 가득 차면 서버가 먼저 위 규칙으로 안 쓰는 사진을 정리해 보고 올려요. 그래도 "저장 공간이 가득 찼어요"가 나오면 오래된 기록의 사진을 빼 주세요.
- 올리다 연결이 끊겨 서버에 반쯤만 저장된 사진은 기록에 붙지 않고(없는 사진으로 봄), 같은 백업을 다시 가져오면 마저 채워져요.

## 6. 백업

- **설정 → 백업 → 내보내기**: 모든 기록과 멤버, 게임 정보가 `ddoddohouse-backup-날짜.json` 파일로 저장돼요. 가끔 받아서 드라이브 등에 보관해 두세요.
  - **사진 포함**(기본 켬): 기록에 붙은 사진과 게임 대표 이미지(원본·작은 사진)도 파일 안에 넣어요. 사진이 많으면 파일이 커져요 (사진 한 장에 최대 1MB쯤). 끄면 기록과 멤버만 담겨요.
- **설정 → 백업 → 가져오기**: 백업 파일을 고르면 기록·멤버·게임·사진 개수를 미리 보여 주고, "없는 것만 추가" 또는 "덮어쓰기"를 골라 되살릴 수 있어요 (같은 id 기준).
  - **가져오는 기록에 붙은 사진만** 먼저 같은 id로 올리고(서버에 다 올라가 있으면 건너뜀) 그다음 기록을 저장해요. "없는 것만 추가"로 건너뛰는 기록의 사진은 올리지 않아요. 새로 만든 빈 서버로 옮길 때도 사진까지 그대로 돌아와요.
  - 잠깐의 연결 문제·서버 오류로 실패한 사진은 두 번 더 올려 보고, 그래도 안 되면 기록을 저장할 때 서버가 없다고 알려 준 사진만 빼요. 사진 없이 내보낸 백업이거나 형식·크기·한도 때문에 서버가 받지 않은 사진도 그 사진만 빼고 기록을 저장해요.
  - 사진 기능 전의 백업(기록에 사진 목록이 없음)을 덮어쓰기로 가져와도 서버에 있는 사진은 그대로 둬요.
- 게임 정보도 같은 id 로 되살려요(대표 이미지를 먼저 올린 뒤). 이름이 같아도 id 가 다르고 그 id 에 연결된 기록이 있으면 다른 게임(판본)으로 보고 따로 가져와요. 연결된 기록이 없는 예전 백업의 소장 게임만 같은 이름이면 '이미 있음'으로 건너뛰어요.
- 저장 한도: 기록 5,000개, 멤버 200명, 게임 정보 1,000개, 사진은 위 5번 참고.

## 7. 로컬 개발 (개발자용)

Node.js 20 이상이 필요해요.

```sh
npm install
npm run dev      # http://127.0.0.1:3000 — 메모리 저장소, 코드는 dev-secret-key-1234 (터미널에 링크가 나와요)
npm test         # API·사진·검증·통계·정적 파일 단위 테스트 (redis-server 가 있으면 실제 Redis·Upstash 경로도 검사)
npm run e2e      # 실제 Chromium(모바일 390×844, 노트북 1440×900·태블릿 1024×768 배치 포함)으로 전체 흐름(사진 올리기·보기·정리·백업 포함) 검사 + 스크린샷
npm run bump-sw  # 앱 파일을 바꿔 배포하기 전에: 서비스 워커 캐시 버전 올리기
```

- `npm run e2e`는 Chromium이 필요해요. `/opt/pw-browsers/chromium`이 있으면 그걸 쓰고, 아니면 `CHROMIUM_PATH=/path/to/chrome npm run e2e`처럼 지정해요. 스크린샷은 `test-results/shots/`(또는 `E2E_SHOTS=폴더`)에 저장돼요.
- 개발 서버 포트·코드는 `PORT=4000 APP_SECRET=… npm run dev`로 바꿀 수 있어요.
- 빌드 단계가 없어요. 파일을 고치고 GitHub에 올리면 Vercel이 자동으로 다시 배포해요.
- 작업 규칙은 [`CLAUDE.md`](CLAUDE.md)에 있어요. 작업은 항상 테스트 → PR → `main` 머지까지 끝내요.

```
css/app.css           디자인 (라이트/다크 토큰, 모바일 우선 → 768px 레일 · 1200px 사이드바, 화면 안 배치는 container query)
css/fonts.css         Pretendard 글꼴 (@font-face, 화면에 나온 글자 조각만 받음)
fonts/pretendard/     Pretendard Variable 조각 파일(woff2) + 라이선스(SIL OFL 1.1)
js/
  main.js             시작, 해시 라우터, 링크의 키 처리, 오프라인 안내, 서비스 워커 등록
  api.js              fetch 래퍼 (x-app-key, 타임아웃, 오류 코드, 사진 올리기 진행률)
  store.js            상태, 기기 로컬 캐시·초안·테마
  stats.js            통계·소장 목록 계산 (순수 함수, node 테스트 가능)
  compress.js         사진 줄이기 (canvas 재인코딩 → EXIF 제거, WebP/JPEG)
  images.js           사진 불러오기 (코드 헤더 → blob:, 메모리 캐시, 화면에 가까워지면 불러오기)
  dom.js ui.js        안전한 DOM 생성 도우미, 공용 UI 부품
  nav.js format.js    이동 도우미, 날짜·숫자 표시
  constants.js        종류·라벨·태그 추천·팔레트
  views/              화면: lock, home, list, collection(소장), game(게임 상세), detail, form(새 기록·수정 폼),
                      game-form(게임 정보 등록·수정 창), game-picker(기록 폼의 게임 검색·선택), stats, members, settings, bits,
                      photos(게임 대표 이미지 칸·예전 기록 사진의 갤러리·뷰어)
api/                  Vercel 함수 5개: data.js(목록), records.js(기록 저장·삭제), members.js(멤버 저장·삭제), games.js(게임 정보 등록·수정·삭제), images.js(사진 올리기·보기·정리)
lib/                  서버 공용 코드 (함수로 배포되지 않음)
  handler.js          인증·레이트리밋·검증·원자적 저장(Lua)·오류 은닉
  images.js           사진 형식 판별(JPEG·WebP)·메타데이터 제거·한도·올리기/정리용 Lua
  auth.js validate.js redis.js
scripts/
  dev.mjs             로컬 개발 서버 (정적 파일 + /api + vercel.json 헤더 흉내)
  bump-sw.mjs         서비스 워커 캐시 버전 올리기
  make-icons.mjs      앱 아이콘 PNG 생성
tests/                단위 테스트(*.test.mjs) + e2e.mjs
sw.js manifest.json   PWA (정적 파일만 캐시, /api 는 절대 캐시 안 함)
vercel.json           보안 헤더 (CSP — 사진은 img-src 'self' data: blob:, noindex 등)
robots.txt            검색엔진 차단
clear-cache.txt       잠금·잠금 해제 정보 지우기 때 불러서 브라우저 캐시(받아 둔 사진)를 비움 (Clear-Site-Data 헤더)
.vercelignore         배포에서 뺄 개발용 파일 (tests/, scripts/, README.md, CLAUDE.md)
CLAUDE.md             작업 규칙 (작업은 항상 main 머지까지)
```

# 또또하우스 기록장

보드게임 · 머더미스터리 · 방탈출 플레이 기록을 모아 보는 **개인 티켓북** 웹앱이에요.
장식을 절제한 티켓 모양 카드에 제목·날짜·평점이 먼저 보이고, 쌓인 기록은 검색·필터·작품별 모아보기로 찾아요.

- **짧게 기록**: 장르 · 제목 · 날짜만 필수 (날짜는 오늘로 기본). 평점(5점, 0.5점 단위, 미평가 가능) · 한 줄 감상 · 사진은 바로, 나머지는 ‘추가 기록’을 펼쳐서.
- **장르별 항목**: 고른 장르의 항목만 보여요.
  - 보드게임: 플레이 인원, 사용한 확장, 내 점수와 순위, 플레이 시간
  - 머더미스터리: 플레이 방식, 플레이 시간, 스토리·몰입도 평가와 감상 (맡은 역할·범인·결말은 스포일러 메모로)
  - 방탈출: 매장·지점, 테마명, 성공·실패, 남은 시간, 힌트 수, 체감 난이도, 공포도 (문제·풀이는 스포일러 메모로)
- **작품과 플레이를 나눠 관리**: 같은 작품을 여러 번 한 기록은 작품 화면에 날짜별로 모이고, 작품 화면에서 새 플레이를 더해요. 이름만 같은 작품(다른 매장의 같은 테마명 등)은 **자동으로 합치지 않아요** — 저장할 때 같은 이름이 있으면 “기존 작품에 추가 / 새 작품으로 저장”을 물어봐요. 잘못 나뉘었으면 작품 정보 수정에서 합칠 수 있어요.
- **스포일러 분리**: 일반 감상(한 줄 감상·상세 후기)과 스포일러 메모를 따로 적어요. 스포일러는 상세 화면에서 기본으로 접혀 있고, 목록 카드와 검색 결과 미리보기에 나오지 않으며, 검색도 스포일러 내용은 찾지 않아요.
- **메인 화면**: 기록장 이름 + 새 기록, 전체/보드게임/머더미스터리/방탈출 탭, 제목 검색(띄어쓰기 무시·초성 검색), 연도·평점 필터, 최근 플레이 날짜순, 카드형/목록형 전환, 작품별 묶기.
- **예시 기록**: 처음 화면이나 설정에서 넣어 볼 수 있어요. ‘예시’ 표시로 내 기록과 구분되고, 한 번에 지울 수 있고, 백업에는 들어가지 않아요.
- PC·휴대폰 반응형, 밝은 크림색 기본 테마(설정에서 어둡게), 오프라인에서도 열려요(PWA).

## 1. 기록은 어디에 저장되나요

**모든 기록과 사진은 이 기기의 이 브라우저 안(IndexedDB)에만 저장돼요.** 서버로 보내지 않아요.

- 새로고침하거나 브라우저를 껐다 켜도 기록과 사진은 그대로예요.
- 다른 기기, 같은 기기의 다른 브라우저(크롬 ↔ 사파리)에서는 보이지 않아요. 아이폰에서는 사파리와 ‘홈 화면에 추가’한 앱도 저장 공간이 따로예요.
- 브라우저에서 ‘쿠키 및 사이트 데이터’를 지우거나, 시크릿(사생활 보호) 창을 닫으면 기록도 지워져요.
- 아이폰·아이패드 사파리는 사이트를 7일 넘게 열지 않으면 데이터를 지울 수 있어요. 홈 화면에 추가해 쓰거나 백업을 자주 받아 두세요.
- 첫 기록을 저장하면 브라우저에 ‘저장 공간 보호(persistent storage)’를 요청해요. 설정에서 상태와 사용량을 볼 수 있어요.
- 사진은 올리기 전에 기기 안에서 줄여서(긴 변 1600px, WebP/JPEG) 저장하고, 이때 촬영 위치(GPS) 같은 EXIF 정보가 빠져요.

이 범위는 앱의 **설정 → 저장 위치와 범위**에도 그대로 안내돼요.

### 백업 (다른 기기로 옮기기)
**설정 → 백업**에서 내 기록을 JSON 파일 하나로 내보내고(사진 포함 선택), 다른 기기·브라우저에서 가져와요.
가져올 때는 “없는 것만 더하기” 또는 “모두 바꾸기”를 골라요. 예전 모임용 기록장(서버 버전)에서 내보낸 백업도 가져올 수 있어요 (아래 6번).

## 2. 실제 접근 제어와 ‘화면에서 가리기’는 달라요

| | 지금 상태 |
|---|---|
| **실제 접근 제어** (개인정보 보호) | **없어요.** 로그인·비밀번호가 없고, 저장된 내용은 암호화되지 않아요. 이 기기·이 브라우저를 열 수 있는 사람은 스포일러를 포함한 모든 기록을 볼 수 있어요. 지금 기록을 지켜 주는 것은 기기의 화면 잠금과 브라우저 프로필이에요. |
| **화면에서 가리기** (스포일러 접기) | 스포일러 메모는 상세 화면에서 기본으로 접혀 있고(펼치기 전에는 화면에 그리지 않음), 목록 카드·검색 결과 미리보기에 나오지 않아요. **실수로 보는 것을 막는 표시 기능일 뿐 보안 기능이 아니에요.** 백업 파일에도 스포일러가 그대로 들어가요. |

앱의 **설정 → 개인정보와 스포일러 보호**에 같은 내용이 나란히 안내돼요.

## 3. 로그인 · 기기 간 동기화 (아직 정하지 않음)

이번 구현에는 로그인과 자동 동기화를 넣지 않았어요. 방식을 따로 정할 수 있도록 저장을 한곳(`js/repo.js`)에 모아 두었어요.

| 선택지 | 장점 | 생각할 점 |
|---|---|---|
| A. 지금처럼 백업 파일로 옮기기 | 추가 비용·계정 없음, 기록이 기기 밖으로 나가지 않음 | 수동, 기기마다 기록이 따로 쌓일 수 있음 |
| B. 예전 방식: 비밀 링크 + 서버(Vercel 함수 + Upstash Redis) | 이미 한 번 만든 구조 (git 기록 `5856e5e`에 있음), 링크만 있으면 여러 기기에서 같은 기록 | 링크가 곧 열쇠라 새면 코드 교체 필요, 개인 계정 구분 없음 |
| C. 계정 로그인 서비스 (Supabase·Firebase 등) | 계정별로 서버에서 막는 **실제 접근 제어**, 기기 간 자동 동기화 | 가입·로그인 화면, 무료 한도·개인정보 처리 방침 확인 필요 |
| D. 개인 클라우드 파일 동기화 (구글 드라이브 등) | 내 저장소에만 보관 | 인증 설정이 번거롭고 동시 수정 충돌 처리 필요 |

**붙이는 자리**
- 쓰기는 모두 `js/repo.js`의 `commit()` 한 곳을 지나가요. 여기서 서버로 보내면(push) 돼요.
- 읽기는 `init()`에서 IndexedDB 를 읽어요. 여기서 서버 것을 받아(pull) `updatedAt`이 새로운 쪽으로 합치면 돼요.
- 작품·플레이·사진은 모두 무작위 id 와 `createdAt`·`updatedAt`(ISO 시각)을 가지고, 지운 작품·플레이는 IndexedDB `deleted` 저장소에 `{id, kind, at}`로 남아서 “지웠다”도 전달할 수 있어요 (예시 기록은 남기지 않음).
- 서버를 붙이면 `vercel.json`의 CSP `connect-src`에 그 주소를 더해야 해요.

## 4. 데이터 구조

```
work (작품)   { id, genre, title, store, branch, cover, createdAt, updatedAt, sample? }
              - store·branch(매장·지점)는 방탈출만. 이름이 같아도 id 가 다르면 다른 작품
play (플레이) { id, workId, date, rating(null=미평가), oneLiner, review, companions[], photos[],
                details{장르별 항목}, spoiler{스포일러}, createdAt, updatedAt, sample? }
              - details: 보드게임 players·expansions·myScore·myRank·durationMin
                         머더미스터리 format·durationMin·story·immersion·impression
                         방탈출 result·remainingSec·hints·difficulty·fear
              - spoiler: 머더미스터리 role·culprit·ending, 방탈출 puzzles, 공통 memo
image (사진)  { id, type, thumbType, full, thumb(ArrayBuffer), width, height, size, createdAt }
```

저장할 때 `js/model.js`가 화이트리스트로 검증해요: 모르는 필드는 버리고, 연결된 작품의 장르 항목만 남겨요.

## 5. 배포 (Vercel, 정적 사이트)

빌드 단계가 없어요. 저장소를 Vercel 에 연결하고 Framework Preset **Other**, Build Command·Output Directory 는 비워 둔 채 배포하면 돼요. **환경변수나 데이터베이스는 필요 없어요.**
앱 파일을 고쳐 배포하기 전에는 `npm run bump-sw`로 서비스 워커 캐시 버전을 올려 주세요.

## 6. 예전 모임용 기록장(서버 버전)에서 옮겨 오기

이 버전은 서버 API 를 쓰지 않아서, **배포하면 예전 서버(Upstash)에 있던 기록을 앱에서 더 이상 불러올 수 없어요.** 예전 버전에 기록이 있다면:

1. **이 버전을 배포하기 전에**, 예전 앱의 **설정 → 백업 → 내보내기**(사진 포함)로 파일을 받아 두세요.
2. 새 버전을 배포한 뒤 **설정 → 백업 가져오기**로 그 파일을 골라요.
   - 예전에는 ‘작품’ 개념이 없어서, 같은 장르·같은 제목(방탈출은 매장·지점까지 같을 때)인 기록을 한 작품으로 묶어요.
   - 함께한 멤버는 ‘함께한 사람’ 이름으로, 스포일러로 표시한 후기는 스포일러 메모로 옮겨요.
   - 멤버별 점수·순위, 태그, 장소, 세부 점수는 새 기록장에 없는 항목이라 가져오지 않아요.
3. 옮긴 뒤에는 Vercel 의 `APP_SECRET`·Upstash 환경변수와 데이터베이스를 지워도 돼요.

백업을 받아 두지 못했더라도, **예전 앱을 쓰던 그 브라우저**에는 마지막으로 불러온 기록 사본이 남아 있어요.
새 버전을 열면 처음 화면에 “예전 기록장의 기록 사본 N개가 남아 있어요” 안내가 뜨고, **가져오기**를 누르면 옮겨져요 (사진은 서버에만 있었으므로 빠져요).
가져오거나 지우면 이 브라우저에 남아 있던 예전 입장 코드도 함께 지워요.

## 7. 로컬 개발

Node.js 20 이상.

```sh
npm install
npm run dev      # http://127.0.0.1:3000 — 정적 파일 + vercel.json 헤더 흉내
npm test         # 모델·검색/필터·백업·정적 파일 단위 테스트
npm run e2e      # 실제 Chromium(휴대폰 390×844 + 데스크톱)으로 전체 흐름 검사 + 스크린샷(test-results/shots/)
npm run bump-sw  # 배포 전: 서비스 워커 캐시 버전 올리기
node scripts/make-icons.mjs   # 앱 아이콘 PNG 다시 만들기
```

`npm run e2e`는 Chromium 이 필요해요. `/opt/pw-browsers/chromium`이 있으면 그걸 쓰고, 아니면 `CHROMIUM_PATH=/path/to/chrome npm run e2e`처럼 지정해요.
